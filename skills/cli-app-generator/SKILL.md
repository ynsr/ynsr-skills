# CLI App Generator

Governs how to build a CLI tool when the user wants something reusable — not throwaway diagnostics.

## Step 0: Is this actually a "tool" request?

- **Use**: "script that reconciles X against Y", "build a CLI tool for downloading movies" — anything reusable beyond one run.
- **Skip, answer inline**: one-liners and quick checks.

Ambiguous → treat as a real tool.

## Step 1: Ask once — audience + missing inputs

Before writing code, ask (in one batch) only what's missing:

1. **Audience — AI agents or humans?** Never guess ("CLIs get piped anyway" is guessing). The request names the consumer ("for agents to call", "for my terminal use") → proceed; otherwise ask. Updating an existing CLI → read the audience line from its AGENTS.md; missing → ask. Record it: full projects in AGENTS.md (`Primary audience: AI agents — CSV/JSON output, non-interactive`), standalone scripts in the `--help` epilog.
2. **Required/high-impact inputs** (credentials, target paths, endpoints) → stop and ask interactively; never invent placeholders or silent defaults. Options with a safe default (`--timeout`) → just default and mention in `--help`.

## Step 2: Tier + stack (pick from DECISIONS.md-verified libraries)

| Tier | Use when | Stack |
|---|---|---|
| **Bash** | Single concern, orchestrating existing CLI tools, no real data structures; escalate to Python past ~300 LOC | bashly (YAML → standalone single file, runs on bash ≥4.2, ble.sh-safe static completions) |
| **Python single-file** | Real parsing, structured data, retries; bash would be unreadable | PEP 723 + typer 0.27 + rich + httpx + questionary wrapper |
| **Python project** | >~1000 lines, multiple modules, distribution, plugins | typer + rich + httpx (+socks) + pydantic + platformdirs + questionary |
| **Go** | Daemon/background service, or single static binary for servers/jump hosts | cobra + fang + huh + go-pretty + own 36-LOC retry helper + slog(stderr) |

Scaffold every tier — don't hand-roll:

```bash
scripts/scaffold.sh --tier <python-project|python-single-file|bash|go> --audience <agent|human> --name <tool-name> [--profiles] [--wizard] [--service] [--dest DIR]
```

Add-ons are tier-scoped: profiles+wizard → python-project and Go; service → Go only; bash/single-file get env vars only. Library versions, licenses, and rejected alternatives: `references/stacks.md`; spike evidence: `DECISIONS.md`.

## Step 3: Universal contract (every tier; `verify-cli` enforces the machine-checkable subset)

1. Stdout carries data only; logs/progress/prompts → stderr.
2. `--output/-o` accepts `table|json|csv|tsv`; `--json` alias. Precedence: `--output` > `--json` > audience default. Human default `table`; agent default `csv` (flat) / `json` (nested). Machine timestamps ISO-8601 UTC.
3. Exit codes `0` success, `1` error, `2` usage, `3` network, `4` partial — 3/4 only when needed; documented in `--help`.
4. Never block on input. `--no-input`, or non-TTY stdin/stdout or `CI` set → fail with an actionable message. Prompt only with a TTY.
5. Honor `NO_COLOR` and `TERM=dumb`; provide `--no-color`.
6. `--version`, `-v`/`-q` on every tool. Destructive actions: `--dry-run` prints the real records/requests; execution needs `--yes`/`--force`.
7. Errors: humans get a styled one-liner + hint; agents (non-TTY or `--output json`) get `{"error":{"code","message","hint"}}` on stderr with matching exit code.
8. Agent tools: `--fields` and `--limit`/pagination on list commands; `schema`/`commands` introspection subcommand (Click tree + pydantic JSON Schema).
9. Human tools: pager for long output; did-you-mean hints where the framework lacks them.
10. Secrets from env vars or 0600 files, never flags. Precedence flag > env > profile > default.
11. Install/uninstall idempotent; uninstall reverses everything.
12. Completion generated by the framework, installed by file drop into the shell's autoload dir; dynamic callbacks read local state only, import lazily, return `[]` on failure. ble.sh-safe.

## Step 4: Install, completions, doctor

Scaffolded `install.sh`/`uninstall.sh` handle it: python-project → `uv tool install --editable .` (source edits propagate; no receipt/stale-guard), single-file → symlink into `~/.local/bin`, guarded best-effort `cli-hub register` at the end (unregister in uninstall). Typer completion needs the 3-line `completion_init()` workaround (`add_completion=False`); details, file-drop paths, zsh fpath, and the `status: ok|missing` doctor contract: `references/install-and-completion.md`.

## Step 5: Services (Go tier, `--service`)

User-scoped systemd unit + linger + `<tool> service install|uninstall|start|stop|restart|status|logs` — mechanics: `references/systemd.md`.

## Step 6: Testing

Python/Go: scaffolded suites (pytest / table-driven `go test`) — ≥75% coverage on core logic, fast real e2e beats inflated unit coverage. Bash: `bats` + inline e2e — pattern: `references/bash-testing.md`. Every skeleton's `check` target = lint + tests + the copied `scripts/verify-cli`.

## Step 7: README, AGENTS, version control

Scaffolded README (one-liner, Install, Usage with real commands, Caveats) and AGENTS.md (audience line, build/test commands, module map, a `cli-app-generator` reference). `.gitignore` per tier with real secrets excluded from the first commit; `git init` + initial commit without asking; no remote → suggest `gh repo create` commands (don't create); free to commit/push to main of generated apps.

## Output

Deliver working files (`chmod +x` scripts) and run `templates/verify-cli <tool> [probe-read] [probe-destructive]` — all checks green before handover. Also exercise `--help` and one real invocation; if install scripts or service subcommands exist, run install → `status` → uninstall. Commit, run gitleaks before the first push.
